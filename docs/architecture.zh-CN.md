# Stick Arcade 项目架构

Stick Arcade 是包含启动器和多款游戏的单一固件。平台负责硬件、界面、设置和联机；游戏负责规则、状态、序列化与绘制。

## 组件

| 路径 | 职责 |
|---|---|
| `src/main.cpp` | 初始化 M5Unified 和平台服务，运行启动器、设置与游戏界面循环。 |
| `src/core/` | 共用类型与服务：`IGame`、固定 60 Hz 步进、输入、网络读写器、游戏内存 Arena、显示缓冲、传感器、声音和持久化设置。 |
| `src/ui/` | 启动器、设置页，以及等待、倒计时、单人、联机和退出流程。 |
| `src/net/net_session.*` | 与硬件无关的匹配和会话状态、主机权威模拟、状态快照、再战和断线处理。 |
| `src/net/net_espnow.*` | ESP-NOW 与 Wi-Fi 无线连接适配。 |
| `src/games/registry.*` | 游戏清单及启动器顺序。 |
| `src/games/<game>/` | 游戏模拟和网络格式，以及游戏画面、卡片和等待背景。 |
| `test_host/` | C++ 规则、核心、网络测试和可选的串口硬件检查。 |

## 运行流程

1. `main.cpp` 初始化显示、设置、输入、声音和游戏注册表。
2. 启动器选择 `GameEntry`；游戏界面创建 `IGame` 实例并显示等待页。
3. 单人模式启动本地模拟。联机模式中，两台设备按游戏和协议标识进行配对。
4. 主机以 60 Hz 推进游戏并序列化完整游戏状态。客户端发送输入并解码收到的状态快照，不运行权威模拟。
5. 游戏视图绘制到平台画布。客户端可通过 `localInput()` 更新仅本地显示所需的即时效果，例如倾斜瞄准。
6. 退出时平台销毁游戏实例并返回启动器。

```text
StickS3 硬件
    │
主循环 ── UI（启动器 / 设置 / 游戏流程）
                    │
                 游戏注册表
                    │
       ┌────────────┴────────────┐
       │ 游戏规则与状态           │ 游戏绘制与音效
       │ IGame，不依赖硬件        │ 画布、事件
       └────────────┬────────────┘
                    │ 编码/解码
       net_session ─┴─ net_espnow
               ESP-NOW 对端
```

## 游戏和网络接口

`src/core/game_iface.h` 中的 `arcade::IGame` 定义了生命周期（`begin`、`step`、`phase`）、输入计数初始化、完整状态的 `encode`/`decode`、可选的本地显示输入和空闲状态、绘制及音效事件。`arcade::GameInfo` 提供游戏 ID、唯一 wire ID、协议版本、实例和 Arena 内存大小、工厂函数、玩家数及屏幕方向。

会话层不依赖具体游戏。HELLO 配对会先检查游戏 wire ID 和协议版本。主机负责权威模拟，客户端发送 `PadInput` 并接收状态快照。后续快照会替代丢失的旧快照。网络包上限为 250 字节，包含会话封装，因此游戏状态编码应保持紧凑。编码格式不兼容时必须增加该游戏的 `protoVer`。联机两端需要兼容的固件。

## 构建环境

`m5stack-sticks3` 包含全部注册游戏；`dev-throwhalla` 和 `dev-bumperduel` 用于单游戏快速迭代；`debug-all` 启用串口调试控制和性能输出。具体配置见 `platformio.ini`。
